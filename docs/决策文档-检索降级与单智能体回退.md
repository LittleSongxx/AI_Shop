# 决策文档：检索降级、通道检疫与单智能体回退

本文只记录已经由源码、测试或运行日志支持的事实，不把本地演示数据包装成生产结论。

## 问题：检索链路的三类失败不是同一回事

RAG 链路里"检索不到"与"检索坏了"是两类问题，处理方式必须不同：

| 失败类型 | 例子 | 错误做法 | 正确做法 |
|---|---|---|---|
| 内容缺失 | 知识库没有该商品/政策 | 让模型自由发挥 | 如实声明无依据，必要时转人工 |
| 能力降级 | rerank 服务超时、ES 不可用 | 整条链路 500 | 有界降级到更弱但可用的组合 |
| 内容被污染 | 知识库文档被投毒、工具结果夹带注入话术 | 让污染文本进上下文 | 标记 + 检疫（隔离），不是整链拒绝 |

## 一、能力降级：有界的退化链，而不是熔断式全挂

从课程项目的 lesson-12/lesson-44 借鉴的核心观点：**降级不是失败，是一条预先定义好的、成本递减的退化链**。

- rerank 不可用 → RRF 权重回退到无 rerank 的混合检索（分数仍可用，只是排序质量下降）；RAG 路由不可用 → 工具检索路径或明确无依据答复。
- 外部能力（视觉 API、rerank）独立熔断 + 有限重试，降级状态在 readiness 预检中可见，但**不阻止商城基础服务启动**。
- 关键区分：降级路径与主路径共用同一份"可验证性"——RAG 的证据门禁、来源引用在降级时依然保留。降级可以损失排序质量，不能损失证据链。

## 二、内容污染：检疫（quarantine），而不是拒绝（reject）

检索内容与用户输入的身份不同：一段被投毒的知识库文档，不该让整个检索请求失败——用户的问题是合法的，是内容脏了。所以对**通道内容**（知识库片段、工具结果）采用"标记 + 检疫"策略：

- **规则同源**：通道扫描与输入防护共用同一张规则表（BLOCKING_RULES / SUSPICIOUS_RULES / SUSPICIOUS_BLOCK_THRESHOLD），规则不维护两份。
- **扫描的是治理后的文本**：Observation 层先做 PII 脱敏、长度裁剪，再对模型实际看到的内容扫描污染——模型看到什么，就按什么判定。
- **两个检疫点**：
  1. RAG 片段在 `retriever._trace_result` 逐条检疫（所有 RAG 路径的唯一组装点，能精确到"剔除哪一条"；比挂在知识库搜索工具上只能整段拒绝更强），被剔除片段记录 `quarantineCount` 与命中规则，并打 `agent_rag_channel_contaminated_total` 指标。
  2. 工具结果在 Observation 层检疫：命中注入话术时，正文被替换为占位符 `[外部工具内容已因安全策略隔离]`，原文只保留在 trace 里，`omittedFields` 记录 `contaminated_content`——模型上下文里不存在污染文本。
- **污染 ≠ 静默**：检疫结果进入 trace 与指标，后续质检能回答"这轮对话里隔离了几条污染内容、命中哪些规则"。

## 三、单智能体回退：复杂路径失败时回到简单路径

多智能体（Supervisor + 专家）与单 Agent ReAct 在 AI_Shop 中是同一服务里的两条路径，而不是两套部署：

- 专家 LLM 异常时记录 `SPECIALIST_FALLBACK` 并切回 Supervisor 的 legacy loop，用户不会看到"系统错误"，只看到一轮略慢但同构的对话。
- 回退路径与主路径共享验证设施：专家产物有 `AgentArtifact` 门禁，legacy loop 同样走工具治理、输入防护和 Observation——**回退降的是编排复杂度，不降安全与可观测性**。

## 取舍与未采用方案

- **不做污染即拒绝**：对通道内容拒绝会导致投毒者可以用"往知识库扔一篇文档"让整个 RAG 功能下线，这是把单点风险放大了；检疫把影响限制在"那一条内容"。
- **不做内容净化改写**：把"忽略之前所有指令"替换成无害表述看似聪明，但改写本身可能引入语义偏差，且难以证明改写后的文本无残留危害；替换为占位符 + 记录原文是最诚实的选择。
- **单 Agent 回退不重新进入多智能体**：回退是单向的（复杂 → 简单），没有"再试一次专家"的循环，避免故障时的无界重试。

## 测试与验证

- `test_channel_guard.py`：规则表身份共享（通道与输入防护是同一张表）、全角/零宽字符混淆、污染工具结果替换为占位符、RAG 片段逐条剔除、全剔后检索无证据、指标增量。
- 降级路径与主路径共用证据门禁的断言在既有 RAG 契约测试中覆盖。

## 60 秒面试复述

检索链路我区分三类失败：内容缺失要如实承认、能力降级要沿有界退化链走（rerank 挂了回退 RRF 混合，证据门禁不降级）、内容污染要检疫而不是拒绝——一段被投毒的知识库文档不该让整个检索下线，所以我在所有 RAG 路径的组装点逐条剔除污染片段，在工具结果进上下文前用同一张规则表扫描，命中就把正文换成隔离占位符、原文只留在 trace 里。多智能体路径失败时单向回退到 legacy loop，回退降编排复杂度，但不降安全与可观测性。
