## 审计范围与方法

本轮检查覆盖 Python Agent 生产路径、Search/RAG/Agent 统一评测器、客服 HTTP 回放、数据集生命周期、不可变 evidence、指标公式、负载模型、测试以及项目对外文档。起点为分支 `refactor/ai-shop-mainline-quality`、提交 `e5b94b9` 上的脏工作树；所有新回放均使用独立 run ID。

采用以下约束：

- 已发布、已归档或已有 `SHA256SUMS` 的结果只读，不原位修补，不用新代码静默重算旧指标。
- 同一 case/qrel 上的修复前后结果只称 paired 或 targeted regression，不称新 final、泛化提升或人工质量提升。
- HTTP verifier、引用结构校验和行为契约只验证可机器判定的执行事实；答案正确性、引用语义支持与 unsafe answer 必须由独立双盲人工评审决定。
- 本地延迟和容量结果不外推为生产 SLO、持续吞吐或线上容量。

联网调研采用的主要依据：

- [scikit-learn：NDCG 定义](https://scikit-learn.org/stable/modules/model_evaluation.html#normalized-discounted-cumulative-gain)：ideal DCG 必须由同一候选相关度 gains 的理想降序产生。
- [scikit-learn：Data leakage](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)：评测输入或其可恢复形式在开发阶段可见，会破坏未见数据结论。
- [Grafana k6：Open 与 Closed model](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/open-vs-closed.md)：测服务承载时应独立调度到达，而不是让前一次响应时间抑制下一次请求。
- [Elasticsearch：Reciprocal Rank Fusion](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion.md)：多路候选应先形成稳定 union，再基于排名融合，避免单路召回提前截断。
- [ALCE](https://arxiv.org/abs/2305.14627)：引用存在、引用正确和引用完整是不同维度，不能用链接格式替代语义支持。
- [RAGChecker](https://arxiv.org/abs/2408.08067)：RAG 缺口应拆到检索与生成层诊断，避免一个总分掩盖根因。

## 评测体系修复

| 缺口 | 风险 | 修复 | 当前边界 |
|---|---|---|---|
| Final 源码暴露未被 claim 阶段检查 | 对已见输入调参后仍可能被标为 final | 新增 fail-closed 源码暴露审计；命中时拒绝 claim，错误和报告均不回显输入文本 | 只修复未来生命周期；历史 v9 不改写 |
| `run/` 回放产物被误算为源码暴露 | 同一历史输入在 report/case/badcase 中重复，污染审计计数 | 源码遍历排除被忽略的运行目录，并补回归测试 | 当前源码口径为 220 个定位，不含本地 run 副本 |
| 暴露扫描只解析 Python/JSON 字符串且忽略短输入 | Markdown/YAML/注释或短 final 可绕过 claim 拒绝 | 扩展常见文本源码格式；扫描开发者可见行；完整精确匹配最低 4 字符，部分匹配仍要求至少 12 字符 | 仍是词法暴露审计，语义改写需靠仓库外数据治理避免 |
| NDCG ideal DCG 使用二元理想列表 | graded qrel 分母错误，随后 `min(1, ndcg)` 会掩盖异常 | 对同一候选 gains 降序计算 ideal DCG，移除上限裁剪 | 历史 NDCG 原样保留；新旧结果不可假装由同一公式产生 |
| 评测轮询为每条 Agent 延迟加入固定噪声 | 400 ms polling 与 150 ms settle 抬高观测延迟 | polling 降至 50 ms，settle 降至 20 ms；报告写明测量配置和上界 | 延迟仍包含最多 50 ms 的终态探测等待 |
| 容量 case 统一要求 LLM | 正确的确定性澄清被误判为失败 | `cs-gold-v1-003` 声明 `agent-runtime`；`028` 保留真实 LLM 路径 | v1 保留错误契约事实，v2 才是修正后观察 |
| 定向子集可能被误写成完整质量评测 | 10 条或 1 条通过被外推到 60 条 | evidence 强制 `normalQualityDenominatorExcluded=true`、`releaseGateEligible=false` | 必须另做完整回放与人工评审 |

## Search 质量修复

已知难例的主要根因不是向量模型本身，而是查询规划和候选边界：比较请求被当成单商品查询，多个子意图候选未做 union，预算/排除/类目/型号等硬约束在 rerank 后丢失，组合采购只返回一个对象，缺货语义和商品证据也不完整。

本轮完成：

- 拆解比较对象、跨类目和组合采购目标，对各子查询召回后合并候选。
- 将预算、排除品牌、型号、类目、库存与 verified qualifier 作为 fail-closed 硬约束，而非只写入软排序提示。
- 分离召回 `raw_query` 与私有约束原文，避免原始约束污染公共 query plan，同时保留约束判定能力。
- 补齐商品/SKU/offer/ranking 证据，使客服最终消息能引用权威商品事实。

## 性能与容量

旧并发阶梯 benchmark 是 closed model：每个虚拟执行流完成后才发下一次请求，响应变慢会自动降低到达率。为避免 coordinated omission，本轮增加固定 2 QPS、12 秒、24 次请求、`maxInflight=16` 的 open-arrival 只读观察，并分别记录 generator delay、queue delay、service latency 和端到端 latency。
