# 客服 v2 来源独立复核说明（2026-08-26）

## 目的与隔离

本任务用 12 条预注册抽样检查历史 v2 additions 标签是否能被一个真正独立的人复现。它验证的是历史标签来源可靠性，不是 v43 答案质量，也不是 v2.1 标签政策重仲裁。

这项工作必须由未参与历史数据构造、旧 A/B 标注、仲裁、模型开发和当前 25 条 v2.1 重标的人完成。保管人只能交付：

- `independent-reaudit.open.jsonl`
- 该表 manifest
- 本任务指定的冻结历史 v1 guideline
- 独立复核保管声明模板

不得交付 source human dataset、候选 expected、旧 A/B 表、agreement、adjudication、模型输出、当前 gold 或 v2.1 新政策说明。历史 v1 与 v2.1 对 `RECOMMENT` 的定义不同；本任务为测量历史链可复现性，严格使用随包的历史 v1 guideline，不能混用 v2.1。

## 填写规则

先把每行 `reviewerId` 的 `UNASSIGNED_INDEPENDENT_REVIEWER` 替换为同一个稳定匿名 ID。只修改 `reviewerId`、`labels`、`comment`；不改 ID、原话、顺序或行数。

五项标签为 `intent`、`riskLevel`、`shouldHandoff`、`handoffSeverity`、`slots`。五项必须整组填写；无槽位用 `{}`；不转人工时 severity 为 `null`，转人工时为 `NORMAL` 或 `CRITICAL`。具体标签边界以随包的冻结历史 v1 guideline 为准。

不知道旧标签是什么是正常且必要的。只依据用户原话和冻结 guideline 作出自己的判断，不向项目开发者或原 reviewer 询问具体 case。

## 保管声明

完成后，reviewer 与 custodian 填写 `independent-reaudit-custody-attestation.template.json`，如实记录身份/外部引用、可见材料、是否独立、是否曾接触旧标签。不能补签不真实的声明。原 `historical-a-b-independence-attestation.template.json` 仅用于能真实追溯旧 A/B 人员时补充历史声明，不能由新 reviewer 代签。

## 预注册门槛

- critical mismatch count：`0`
- intent agreement：`>= 0.80`
- risk agreement：`>= 0.90`
- handoff agreement：`>= 0.90`
- slot exact agreement：`>= 0.70`

任何一项失败，扩大到 additions 全 60 条独立复核；不得重抽一批更容易的 12 条。即使全部通过，也只增加历史 provenance 可信度，不能恢复 external unseen 资格，不能消除已知 v2.1 标签政策冲突。
