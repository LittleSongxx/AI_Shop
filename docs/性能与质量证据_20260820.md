## 质量结论

- Search 的主质量短板是多目标召回和排序，而不是运行失败：`Recall@10 macro/query=0.962121`，补充的 qrel micro 视图为
  `52/56=0.928571`；3 个 query 共漏掉 4 个相关商品，另有 5 个 MRR 和 10 个 NDCG 排序 badcase。
- RAG 的 grounded faithfulness、citation support、no-answer accuracy 在冻结样本上均为 `1.0`，但有 3 次 query expansion
  Provider failure，均走安全 deterministic fallback；它们是诊断信号，不是“零故障”证明。
- Agent 的工具路由/参数样本没有坏例，但 P95 本地延迟为 `17077.8 ms`，两个政策/记忆 case 构成长尾；客服 intent/slot/handoff
  还没有独立人工金标。

v9 final 一次性执行 125 条 holdout，三域硬门禁通过。Final 的 SHA256SUMS digest 为
`94edeb894f3e2d36f597cb9cc9796d6e0e6f6b81da08f030b8723435e441c11a`。`50/50`、`25/25`、`pass^8=1.0` 只说明声明的
安全、契约和可靠性门禁满足，不能替代上面的质量指标，也不证明线上转化、生产容量或开放世界可靠性。

## 运行与统计口径

- 所有 Python 命令使用 `/home/song/miniconda3/envs/shop/bin/python`；运行前通过 MySQL、Redis、RabbitMQ、Elasticsearch、Java Gateway、
  Agent、Embedding、Rerank 和 LLM preflight。
- 运行模式是 `LOCAL_FULL_STACK`。P50/P95/P99 是客户端观察到的本地完整链路延迟；P99 样本少于 100 时仅作描述性统计。
- 二项指标使用 95% Wilson 区间；连续和 ranking 指标使用 percentile bootstrap。区间不会被门禁阈值替代。
- 正常质量分母不包含故障注入 case；故障只按预声明 recovery contract 判分。provider failure、fallback、partial、deadline 和拒绝原因
  仍然逐条记录，不会被抹成零失败。

## Final 主质量指标

完整的分母、95% 置信区间、badcase ID、商品名称和复盘假设以 scorecard 为准；下表保留与历史 summary 兼容的宏平均点估计。
门禁指标在本节后单独列出，不作为优展示。

### Search（n=50）

| 指标 | 值 | 说明 |
|---|---:|---|
| Recall@10 macro/query | 0.962121 | 44 个 qrel query；3 个漏召回 query |
| Recall@10 micro/qrel | 52/56 = 0.928571 | 直观显示漏掉的 4 个相关商品 |
| MRR@10 | 0.937500 | 5 个排序 badcase |
| NDCG@10 | 0.920521 | 10 个排序 badcase |

具体 case ID、漏掉的商品、返回顺序和 95% CI 见 scorecard；R@3/R@5 及 P95 只作为支持性诊断。

Search slices 为精确型号数字品牌 10、中文同义口语 10、预算结构化 8、否定排除 8、无结果冲突 6、fallback/partial 4、
类目品牌比较 4。每个 slice 的主质量指标单独计算；硬约束、无结果、正常 Provider completeness 和错误类型属于门禁，不用平均分掩盖单 slice 失败。

### RAG 最小事实安全证据（n=50）

grounded faithfulness、citation support、no-answer accuracy 和 answerable 子集的 Retrieval Recall@5 均为 `1.0`；这些是当前
lexical/规则下界和事实安全证据，不是人工语义准确率，也不与 InsightVault 的深文档 RAG 主指标重复。invalid citation、severe safety
violation、runtime error 属于必须 100% 的门禁。Retrieval 指标只对 29 个 canonical qrel 的 answerable query 计分，不能把样本数误读成
50 个独立人工标注。

RAG final 有 3 次 query-expansion failure，均明确记录为 provider failure 后的安全 deterministic fallback；它不改变 lexical/fact/
citation 分母，也不被描述为“零故障”。RAG latency P50/P95/P99 为 `1825.4/4246.7/4525.3 ms`，属于本地完整链路描述。

## AI 客服下一轮只补四项指标

当前没有独立人工金标，不能把 Agent 的工具契约通过率当作客服理解准确率。秋招窗口只补：`intent Macro-F1`（附逐 intent F1 和
confusion matrix）、高风险 intent Recall、关键 slot entity/span F1 与请求级 Exact Match、handoff Recall 与严重漏转人工率。
每项都必须带标注分母、置信区间和错例 ID；在这套金标建立前，不报告客服准确率、情绪识别或开放世界成功率。

## Semantic shadow judge

Final semantic shadow 为 `50/50 available`、disagreement `0`、`shadowOnly=true`、`humanGroundTruth=false`。每个 claim 记录 judgeVersion、
prompt hash、model/provider fingerprint、timeout/重试、claim/span/evidence 和 `SUPPORTED`/`UNSUPPORTED`/`CONTRADICTORY`/
`UNDECIDABLE` label；调用失败记录 `UNAVAILABLE`。Lexical、fact ID、引用和 grounded faithfulness 继续作为可审计信号，semantic judge
在独立人工校准前不进入 hard gate，因此不能称为人工准确率、人工一致性或事实真值。

## 故障注入矩阵

只在 evaluation scope 激活的 `FailureInjectionScope` 覆盖：BM25/vector timeout/5xx/空结果、Embedding timeout/异常/断路器拒绝、
Rerank 异常、Java 商品/库存/报价 timeout/5xx/partial、LLM timeout/5xx/malformed、Redis checkpoint、worker deadline、MCP 失败、
重试和重复确认。每个 scenario 预声明 fallbackAllowed、unsafeAnswer、hardConstraintBypass 和 terminalState，并检查 failure trace、
降级标识、deadline、硬约束、RAG 拒答/降级、Agent 幂等与恢复后的下一请求。

v9 resilience package `fault-v9-20260822` 报告 12/12 recovery contracts、生产边界硬场景 11/11，通过门禁；1 个 harness shadow
场景单独标记，不混入生产边界结论。
