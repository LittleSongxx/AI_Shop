## 2. 关键优化与排错

1. 收敛到 `evaluation/` v3 协议：统一 case、slice、trial、usage、state diff、fault 和 semantic shadow 字段；所有执行复用 preflight、脱敏、哈希和 fail-closed。
2. Search 固定七类切片，逐 slice 输出 Recall@3/5/10、MRR、NDCG、no-result、硬约束、Provider completeness、尾延迟和拒绝原因；加入预算/排除/无结果/精确型号/partial Provider metamorphic checks。
3. RAG 保留 lexical/fact/citation/faithfulness 硬门禁，增加 claim-level semantic shadow；记录 judge 版本、prompt/model fingerprint、span、证据 ID、超时和 abstain，失败记 `UNAVAILABLE`。
4. Agent 增加独立 `pass^5`/`pass^8` 重复运行、独立 trial/user/request/idempotency key、Episode/工具字段、Java authoritative before/after hash、结构化 diff 和重复副作用计数。
5. 增加故障注入 scope，覆盖检索、Embedding、Rerank、Java 快照、LLM、Redis checkpoint、Worker deadline、MCP、重试和重复确认；故障样本独立于正常质量分母。
6. 统一 usage/cost：Provider 缺 usage 标 `MISSING_USAGE`；无可信单价时 `costCny=null`，不把未知写成零。
7. 用隔离真实 MySQL 做 1/10/50/100 候选 batch 与 N+1 benchmark，补 round trip、连接使用、P50/P95、错误率和 rollback probe。
8. 建立 current/archive/lifecycle/SHA-256 链：v2 通过 final 和 v3-v8 失败 final 只读归档；`.runs` 只保留 v9 development/regression/final；v9 final freeze 后不重跑、不改分母。
9. 修复影响主线的业务问题：取消提案错误路由、RAG lexical 安全契约、幂等/库存/订单状态边界、Java-Python 内部断言和消息补偿路径。

本次外部核验的主要一手/原始来源：

- [MCP Authorization Specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)：HTTP MCP 的资源服务器、OAuth 发现、resource binding 和 token 安全边界。
- [MCP Specification](https://modelcontextprotocol.io/specification/2025-06-18)：client/server、capability negotiation、tools/resources 和 trust boundary。
- [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：checkpointer 是 thread-scoped，store 才是跨 thread 长期记忆；持久化增长需要 retention/pruning。
- [OpenTelemetry GenAI semantic conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/)：模型、Provider、token、操作和错误字段应统一，当前项目还需补齐 agent/tool 语义映射。
- [OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/) 与 [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework)：把注入、数据污染、权限、监控和风险治理落为可验证控制。
- [Elasticsearch rank evaluation](https://www.elastic.co/guide/en/elasticsearch/reference/current/search-rank-eval.html)：qrel/rank evaluation 支持检索分层评测，和当前 slice 设计一致。
- [Redis distributed locks](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)：单副本 failover 可能破坏互斥；锁必须有唯一值、租约和明确故障假设。
- [MySQL 8.4 EXPLAIN](https://dev.mysql.com/doc/refman/8.4/en/explain.html)：用执行计划/实际执行统计验证慢 SQL，不能只凭应用耗时猜原因。
- [RAGChecker](https://arxiv.org/abs/2408.08067)、[tau-bench](https://arxiv.org/abs/2406.12045)、[RAGAS](https://arxiv.org/abs/2309.15217)：支持检索/生成分层、claim 诊断和最终状态驱动的 Agent 评测；论文结果不替代本项目真实 trace。
