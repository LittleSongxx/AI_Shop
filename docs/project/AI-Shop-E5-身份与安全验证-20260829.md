# E5 身份与安全验证（2026-08-29）

状态：`CONTROLLED_PREPROD_ONLY`；本批收口的是 Agent 直连和浏览器边界，不能外推为
多租户生产安全、正式渗透测试或线上 SLO。

## 本批收口

- 认证后的用户现在有服务端生成的 `Principal(subject, kind, authSource)`。WS
  connection scope 只绑定该 principal，消息正文中的 `userId` 不参与身份选择；现有
  Java `X-Agent-User-Id` 委托信道和按用户服务层归属校验保持不变。
- WebSocket `/ws`、`/ws/` 和 `/ws/admin` 在认证后检查精确 Origin。Cookie 会话必须带
  同源 Origin；脚本/评测客户端使用 header token 时可以不带 Origin，但只要带了就必须
  命中显式 allowlist 或请求 Host 的同源值。`null`、带路径的伪 origin 和通配符均不放行。
- Cookie 鉴权的 HTTP `POST/PUT/PATCH/DELETE` 同样执行 Origin-based CSRF 检查，双凭证
  不一致直接拒绝。WS 每帧以 UTF-8 字节数限制，入站帧（含 heartbeat）按 principal
  走 Redis 固定窗口限流；限流存储不可用时关闭连接而不是放行无限流量。
- Agent API 声明的 request body 超过 `HTTP_MAX_REQUEST_BYTES` 返回 `413`；消息正文仍
  由既有 `MAX_INPUT_CHARS` guardrail 限制。Java Gateway 现在同时保护精确 `/ws` 路径，
  并为 `agent-ws` 注册 Sentinel 路由规则，避免 `/ws` 绕过 `/ws/**` 的认证/流控匹配。
- Java session 的 Redis TTL 是过期权威；Python 认证层同时拒绝 `TTL<=0` 和序列化会话中
  已过期的 `exp`/`expiresAt` 等字段。没有新增 JWT、租户表或 RLS 迁移。

## 配置边界

| 配置 | 默认 | 说明 |
| --- | ---: | --- |
| `WS_ALLOWED_ORIGINS` | 空 | 空值按请求 Host 做同源比较；生产需显式配置反向代理对外 Origin |
| `CSRF_PROTECTION_ENABLED` | `true` | 仅影响 Cookie 鉴权的 unsafe HTTP；header token 不依赖该防护 |
| `HTTP_MAX_REQUEST_BYTES` | `262144` | Agent API 声明 body 上限 |
| `WS_MAX_FRAME_BYTES` | `65536` | 单个 UTF-8 WebSocket frame 上限 |
| `WS_RATE_LIMIT_WINDOW_SECONDS` / `WS_RATE_LIMIT_MAX_MESSAGES` | `60` / `120` | 每用户/管理员入站 frame 窗口 |

生产环境在 CSRF 开启时必须提供 `WS_ALLOWED_ORIGINS`；默认列表不会被猜测为线上域名。

## 限制与下一步

- Origin/CSRF 是浏览器边界防护，不替代 Gateway、Java 领域服务和 action token 的归属
  校验；当前目标仍是单店受控闭环，不做 B2B tenant/RLS。
- request body 的早期门禁依据 `Content-Length`；部署层仍应配置反向代理/网关的实际
  streaming body limit。没有做全量 fuzz、渗透测试、跨区域部署或长期压测。
- Redis TTL 探针在真实 Redis 上 fail-closed；仅实现最小兼容层以允许只提供 `get` 的单测
  double。不能据此声称所有外部身份提供方的 session revocation 延迟已测量。
- Text2SQL 继续保持 `TEXT2SQL_STATUS: FROZEN`；本批未修改其代码、unseen 或历史证据包。
