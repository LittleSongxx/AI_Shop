## 已验证事实

- `没发货的耳机我要退款` 在真实页面链路中返回 `ACTION_CONFIRM`，动作类型为 `REFUND`，绑定订单 `SM202608050002` 和唯一订单项；卡片仍是 `status=0` 提案状态。测试随后读取 Java 订单事实，确认订单/订单项仍为原状态，未调用退款确认写接口。
- `我收到的东西坏了` 返回含多个候选的 `ORDER_SELECTION`。选择第一个候选后得到 `CREATE_SUPPORT_CASE` 提案；重复提交同一选择返回相同 `messageId`，改选第二个候选返回 HTTP `409`，证明选择状态和冲突边界在真实 HTTP/浏览器链路中可观察。
- 两条用例均在 mobile Chromium 通过；trace 可复核登录、会话 WebSocket、Agent 消息、历史轮询、候选选择及订单事实请求。

## 边界

- 用例最终路径包含规则路由和确定性工作流；即使运行中出现 Provider/RAG 辅助调用，也不能把这两条浏览器结果写成 LLM 答案正确率或客服语义质量。
- 没有执行退款、创建工单、支付、人工转接或真实用户数据操作；测试账号和订单是本地受控 fixture。
- 单次受控浏览器运行不能推出 CSAT/FCR、线上 SLO、无人值守高并发、unseen 泛化或生产写入成功率；E57 HTTP/LLM 包仍需独立人工答案盲审。
