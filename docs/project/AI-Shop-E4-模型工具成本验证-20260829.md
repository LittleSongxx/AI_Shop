# E4 模型、工具与成本验证（2026-08-29）

状态：`CONTROLLED_PREPROD_ONLY`；本批补齐配置、保护和可观测性，不代表线上 SLO、持续吞吐或无人值守生产能力。

## 本批收口

- 主模型和 fallback 模型可分别配置 API key、OpenAI 兼容端点、网络超时和 SDK
  重试预算：`LLM_FALLBACK_API_KEY`、`LLM_FALLBACK_BASE_URL`、
  `LLM_FALLBACK_TIMEOUT`、`LLM_FALLBACK_MAX_RETRIES`。留空的 endpoint/key/超时/重试
  继续继承主配置，兼容现有部署；只读交互 fallback 默认把 SDK 重试预算限制为 `0`，
  显式配置后仍是有限重试。
- 非流式和流式 Agent 调用都经过现有 `CircuitBreaker`。熔断键只含
  `primary|fallback`、端点 host 和模型名，不含密钥；5xx/超时计入失败，半开只放一个
  探针，用户取消释放探针而不把用户行为误报为 Provider 故障。熔断拒绝记录为
  `LLM_CIRCUIT_OPEN` / `MISSING_USAGE`，可触发安全的只读 fallback。
- fallback 绑定显式只接收 `READ_TOOLS`，不会因为主模型故障把写提案工具暴露给备模型；
  写操作仍由原有确认卡、Java 事务校验和幂等账本保护。
- 新增确定性 `aishop-tool-manifest/v1`：每个受治理工具包含 `health`、
  `version`、`owner`、`entitlement`、`timeoutSeconds` 和 `requiresConfirmation`。
  远端 MCP 注册表缺工具或出现未知工具时 manifest 为 `DEGRADED`；未知工具不会被放行。
  `/health` 的 `toolManifest` 反映当前 MCP contract 探针，客户端
  `McpStreamableClient.tool_manifest()` 可进一步对账 live registry。
- 每次 run 的现有 usage ledger 继续只使用 Provider 返回的真实 token。可信价格缺失为
  `UNPRICED`，usage 缺失或熔断拒绝为 `MISSING_USAGE`，费用保持 `null`，绝不把未知费用
  记作 `0`。

## 限制与下一步

- 熔断状态沿用当前进程级 registry；本批没有把它升级为跨进程 Redis 状态，也没有做全量
  fault injection、长时间 soak、生产部署或正式 SLO。
- 当前成本仍是运行时 usage/配置价口径，不是供应商账单对账；`UNPRICED`/`MISSING_USAGE`
  不能用于宣称单位成本、CTR/CVR、GMV 或 CSAT/FCR。
- Text2SQL 继续保持 `TEXT2SQL_STATUS: FROZEN`；本批未修改其代码、unseen 或历史证据包。
