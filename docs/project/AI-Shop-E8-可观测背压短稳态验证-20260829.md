# E8 可观测、背压与短稳态验证（2026-08-29）

状态：`CONTROLLED_PREPROD_ONLY`。本批把 browser → Agent gateway → MQ/worker → Java/MCP
链路的相关性与 bounded backpressure 变成可观测契约；不宣称线上 SLO、吞吐或长期稳定性。

## 本批收口

- 流式发布新增 `agent_stream_publish_total{result}`；Redis Pub/Sub 失败计数后继续抛错，
  不把丢帧伪装成成功。
- WebSocket fan-out 改为每连接并行、单连接有界发送（默认 `WS_SEND_TIMEOUT_SECONDS=2`）。
  超时或发送异常的 socket 会被移除，其他浏览器不再被慢连接拖住；无连接、成功、超时、
  异常分别进入 `agent_ws_delivery_total{surface,result}`，并记录发送时延。
- Redis topic listener 暴露 `/health` observability.websocket 的 `up/taskState/lastError`，
  订阅失败和运行时退出进入 `agent_ws_listener_failure_total`；停止时清理订阅和资源。
- Agent WebSocket 帧对 `runId/requestId/episodeId` 做低基数完整性计数；HTTP span、MQ headers、
  Worker `agent.task.consume`、Episode、Java internal headers 和 MCP child span 沿用同一组关联值。
- 有界队列的 overload 分支计入 `agent_backpressure_total{queue,reason}`；Worker 在消费时记录
  `agent_queue_age_seconds`，取消请求记录 `agent_cancel_latency_seconds`。已有
  `agent_task_backlog`、`agent_task_inflight`、Episode queue/drop 指标保持不变。
- 没有建设持久 chunk event-store：chunk 仍是 Pub/Sub-only，终态通过现有 durable message/task
  ledger 与前端 envelope/reconciliation 收口。

## 边界与后续

- `releaseGateEligible=false`、`unseen=paused` 保持不变。当前证据不覆盖线上丢流率、取消
  P95、队列年龄 SLO、并发容量、CTR/CVR/GMV 或 CSAT/FCR。
- Episode writer 仍是 bounded、允许在队列满时丢弃非关键观测；丢弃量可由现有指标发现，
  不把观测写入失败改写为业务成功。
- 若要把终态回放升级为持久 chunk 日志、做全量 fault injection/正式 SLO、或扩大到多租户，
  需要另行确认路线与证据托管策略。
