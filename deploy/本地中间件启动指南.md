## 首次初始化库（必做）

MySQL healthy 后，在 PowerShell：

```powershell
# 在仓库根目录 AI_Shop/ 下执行
$mysql = { param($f) Get-Content $f -Raw -Encoding UTF8 | docker exec -i aishop-mysql mysql -uroot -proot --default-character-set=utf8mb4 }

& $mysql .\sql\00_create_databases.sql
& $mysql .\sql\00b_nacos_seata_databases.sql
& $mysql .\sql\14_nacos.sql
& $mysql .\sql\15_seata.sql
& $mysql .\sql\16_seata_undo_log.sql
# 再按上线检查清单执行 01…10、13
```

或运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\init-mysql-meta.ps1
```

## 一键启动

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\start-middleware.ps1
```

```powershell
cd .\deploy
$env:SEATA_IP=(Get-NetIPConfiguration | Where-Object IPv4DefaultGateway | Select-Object -First 1).IPv4Address.IPAddress
docker compose -f docker-compose.middleware.yml up -d
docker compose -f docker-compose.middleware.yml ps
```

## 端口与账号

| 服务 | 地址 | 账号 / 说明 |
|------|------|-------------|
| MySQL | `127.0.0.1:3306` | root 仅用于引导；运行账号 `aishop` 只有 DML 权限，迁移账号 `aishop_flyway` 独立，密码见 `run/runtime.env` |
| Redis | `127.0.0.1:6380` | 密码见 `run/runtime.env`；容器内仍是 6379 |
| RabbitMQ | `5673` / http://localhost:15673 | 账号与密码见 `run/runtime.env`；容器内 5672 / 15672 |
| Nacos API / 控制台 | `127.0.0.1:8848` / http://127.0.0.1:8848/nacos/ | 用户 nacos；随机密码见 `run/runtime.env`；MySQL 持久化，API/控制台鉴权开启 |
| Elasticsearch | http://127.0.0.1:9200 | 自建镜像含 **analysis-ik**（`aishop-elasticsearch:8.19.19-ik`） |
| Sentinel | http://127.0.0.1:8858 | sentinel / sentinel |
| **Seata** | TC `${SEATA_IP}:8092` | 注册到 Nacos `SEATA_GROUP`；优先使用 WSL 非 `127/8` 的本地回环别名，否则绑定宿主可达地址；镜像自建（驱动在 `/seata-server/libs`） |

> Redis / RabbitMQ / Seata 的宿主机端口刻意 **+1** 偏移，避免与本机已装的同类服务抢端口；
> 容器内端口不变，所以容器互通用默认端口即可。
>
> `application.yml` 和 Agent 的 `settings.py` 里的**默认值已经是偏移后的端口**
> （6380 / 5673 / 8092，RabbitMQ 账号 `aishop/aishop`），所以不传环境变量也能连上。
> 这不只是图方便：本机常有装在 6379 / 5672 的 Redis 和 RabbitMQ，默认值要是留在标准端口，
> 服务会**静默连上本机那一个**——连得通、但读写的是错的实例，比连不上更难查。
>
> Nacos 固定在 **2.5.3**：应用侧依赖 Nacos 3.0.3，而 Seata 2.5 Server 内嵌
> Nacos 1.4.6 注册客户端。该组合使用空字符串作为旧版默认 namespace；不要把
> `NACOS_NAMESPACE` 写成字面量 `public`，否则 Nacos 3 客户端会与 2.x Server 的
> 默认 namespace 语义不一致。
>
> `start.sh` 保留 MySQL root 只做数据库引导，并自动创建 DML 运行账号 `aishop`、
> 迁移账号 `aishop_flyway`、Nacos 账号 `nacos_app` 与 Seata 账号 `seata_app`。
> Java Flyway 与 Agent Alembic 使用迁移账号，常驻请求与 Worker 使用 DML 账号；
> Nacos/Seata 仅拥有各自 schema 权限。旧版 `root` 业务配置会在未显式覆盖时自动迁移；Java 连接池默认
> `minimumIdle=1`、`maximumPoolSize=4`，Agent 默认 `1..8`，Seata 本地池默认 `1..8`，
> MySQL 本地 `max_connections=100`，避免十余个进程把连接和内存吃满。所有选定凭据会以
> Shell 转义格式写入权限为 `0600` 的 `run/runtime.env`，后续重启沿用同一组值。
>
> RabbitMQ 使用 460 MiB 绝对内存水位，而不是按宿主机内存计算的相对比例；该值低于默认
> 768 MiB 容器上限，可在 cgroup OOM 前触发发布流控。
>
> 单节点本地 Elasticsearch 默认使用 `ES_INDEX_REPLICAS=0`，避免副本无法分配导致集群长期
> `yellow`；多节点部署应按节点数设置为 `1` 或更高。

容器互通主机名：`mysql`、`redis`、`rabbitmq`、`nacos`、`elasticsearch`、`sentinel`、`seata-server`。  
宿主机上的 Java 微服务通过 Nacos 获取 `${SEATA_IP}:8092`。Seata 2.5 不接受
`127.0.0.1` 作为注册地址；`start.sh` 会优先选择 WSL 的非 LAN 回环别名，回退到网卡地址时
会打印安全警告，应由宿主防火墙限制为可信网络。

## Seata 事务组

- 模式：**AT**（`seata.data-source-proxy-mode: AT` + 自动数据源代理）
- 客户端仅 order/stock/coupon/cart/pay 引入 Seata；admin 等不引入
- 客户端 `tx-service-group`: `aishop_tx_group` → Nacos `SEATA_GROUP@@seata-server`
- 下单入口：`OrderInfoServiceImpl.postOrder` 使用 `@GlobalTransactional`
- 业务库 `undo_log`：`aishop_order` / `aishop_stock` / `aishop_coupon` / `aishop_cart` / `aishop_pay`（`sql/16_seata_undo_log.sql`）
